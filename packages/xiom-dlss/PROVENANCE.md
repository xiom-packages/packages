## 2. License: NVIDIA RTX SDKs License (CLOSED -- record, never vendor)

The clone's `LICENSE.txt` is the **NVIDIA RTX SDKs LICENSE** ("This license
is a legal agreement between you and NVIDIA Corporation ... governs the use
of the NVIDIA RTX software development kits, including the DLSS SDK, NGX
SDK, ...").  Key constraints read at the pin (paraphrased for the record;
the license text itself is not reproduced here or in the package):

- distribution of SDK software is only permitted as incorporated in object
  code form into an application with material additional functionality,
  under distribution requirements (not as a standalone product);
- modification is permitted only for sample source code;
- **section 4.e**: the SDK may not be used in any manner that would cause it
  to become subject to an open source license;
- no reverse engineering, decompilation or disassembly; no removal of
  notices.

Consequences for this package (all enforced):

1. No NVIDIA header, source, doc, `.lib` or `.dll` is copied into the tree.
2. `xiom.dlss` (MIT OR Apache-2.0) contains only OUR code and INDEPENDENT
   declarations of interface facts (export names, parameter key strings,
   numeric enum/code values) -- the same facts without which no interop is
   possible, and the same category of facts the FFmpeg reference-only
   precedent records (symbol names / ABI values).
3. The runtime modules are loaded at run time from the user's own
   installation; they are never redistributed, downloaded or committed.
4. The suite never downloads binaries; the optional present path only
   probes a user-provided directory.

## 3. What was studied

- `include/nvsdk_ngx.h` + `nvsdk_ngx_defs.h` + `nvsdk_ngx_params.h`
  (core entry points, result codes, feature enum, parameter interface and
  key defines), `nvsdk_ngx_vk.h` + `nvsdk_ngx_defs_vk.h` (Vulkan entries),
  `nvsdk_ngx_defs_dlssd.h` (DLSS-RR), `nvsdk_ngx_defs_dlssg.h` (DLSS-FG),
  `nvsdk_ngx_helpers*.h` (documented call sequences re-expressed in XIOM:
  create/evaluate parameter order, the optimal-settings sequence).
- `include/nvsdk_ngx_loader.h` (core module names and the driver-path
  search the SDK itself documents) -- our loader implements the
  application-visible part of it (bare names + common locations).
- `lib/Windows_x86_64/*/nvngx_dlss*.dll` export tables via
  `llvm-objdump -p` (observed export counts and names; used ONLY as
  verification oracles, recorded in `SPEC.md` section 2).
- `samples/` and the programming-guide PDFs were NOT needed.

## 4. Reflex scan evidence

At the pin, `include/*.h` contains **no** Reflex SDK declarations: a scan
for `Reflex`, `PCL`, `Latency`, `Sleep`, `NvLowLatency`, `NvAPI` across
`include/` returns zero matches.  The task's conditional ("Reflex ... if
covered by the same headers") is therefore negative: no Reflex surface is
declared; `DLSS_REFLEX_COVERED = false` documents it and the suite reports
a typed scope SKIP.

## 5. Derived vs independent

**Independent (XIOM-authored, MIT OR Apache-2.0):**

- `src/surface.xi` -- GENERATED by `tools/gen_surface.py` from the pinned
  headers: 85-entry table (names + runtime spellings + groups; every
  declared name verified against the headers by the generator), 435
  parameter keys, 74 effective-key byte codes, plus the per-group count
  pins.  No comment text or code from the headers is copied; only the
  interface facts.
- `src/dlss.xi` -- loader, classification, entry accessors, typed parameter
  C API wrappers, the DLSS-SR typed flow (create/evaluate/destroy/optimal
  settings), capability queries, UTF-16LE path helper, enum/result
  constants.  Written against the studied headers; the create/evaluate
  parameter ORDER re-expressed from the pinned helpers as our own code.
- `tools/gen_surface.py` -- the regeneration tool (committed; run with the
  pinned clone present; `--check` verifies the committed output).
- `tests/test_conformance.xi` -- surface/SKIP checks (no NVIDIA test
  vectors exist and none were imported).

**Upstream (studied, never committed):** everything under `E:\repos\DLSS`.

## 6. Link model

No link step for the runtime: `port.args.json` is absent (pure XIOM
modules; `src/surface.xi` imports only the stdlib builder), and runtime
integration is `xiom.ffi.dl` dynamic loading of the user's modules:
`nvngx_dlss.dll` (DLSS-SR), `nvngx.dll` / `_nvngx.dll` (NGX core proxy),
`nvngx_dlssg.dll` (FG), `nvngx_dlssd.dll` (RR).  All are optional and
SKIP-safe.
