## 0.3.0 (this touch, 2026-10-13)

Driven by the engine pipeline ask (relay `REL-20261013-1926-packages`, wave
A2: "zstd container framing"): N independently compressed frames in one
container with a per-frame offset/size index, so an engine can seek and
decode chunks out of order.

- Own simple format `ZSTC` v1: 16-byte header (magic/version/flags/count/
  index_offset) + raw frames + 12-byte-per-frame index (offset, compressed
  size, decompressed size). Empty container valid; exact-size layout enforced
  at open.
- Writer: `zstd_container_write` (N frames) and the streaming-ish
  `zstd_container_builder_new/append/finalize`.
- Reader: `zstd_container_open` (index validation only), `frame_count`,
  accessors, `seek` (absolute frame offset) and `frame_at` (owned
  decompressed bytes, any order, repeatable).
- Typed error catalog (`zstd.container: ...`); corrupt/truncated containers
  never crash -- covered by suite checks (truncation, magic/version/flags,
  corrupt index entries, corrupt payload, size fraud).

## Phase 2 (next touches)

1. Streaming: `ZSTD_createCCtx`/`ZSTD_compressStream2`/`ZSTD_createDCtx`/
   `ZSTD_decompressStream` with owned context handles and reusable buffers;
   in-memory streaming first, file streaming when the fsync/stdlib gaps close.
2. Dictionaries: `ZSTD_createCDict`/`ZSTD_compress_usingDict` plus
   `ZDICT_trainFromBuffer` (already in the amalgamation).
3. Parameters: `ZSTD_CCtx_setParameter` (checksum flag, window log, long
   mode), `ZSTD_getCParams` for level bounds.
4. Container follow-ups (consumer-driven): decide with the engine pipeline
   whether ZSTC needs a checksum field, a per-frame uncompressed-size
   override for streaming-style frames (content size unknown), or a
   larger-than-u32 offset variant; keep the v1 layout frozen for the format
   version bump procedure.
5. Consumer check-in: XVECTOR/ORBITDB/PULSE store formats may want a
   `zstd`-compressed segment option; keep the one-shot API stable for them.
6. Re-pin cadence: track upstream releases; regenerate with the documented
   combine command (SPEC section 2) and re-run the clone header parity check.
