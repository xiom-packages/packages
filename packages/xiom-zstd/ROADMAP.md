# xiom.zstd -- Roadmap

**Version**: v0.2.0 | **Compiler**: xiom v0.64.1 | **Last updated**: 2026-10-08

## Current state

| Criterion | Status |
|-----------|--------|
| Vendored amalgamation (G2 pinned) | Done -- zstd 1.5.7, generated by official combine.py |
| FFI core (single confined module) | Done |
| One-shot compress/decompress | Done -- 8/8 x2, real ratios |
| Frame size + error reporting | Done |
| Streaming contexts (`ZSTD_CCtx`/`ZSTD_DCtx`) | Phase 2 |
| Dictionaries (`zdict` API) | Phase 2 |
| Parameters (checksum, window, long mode, level bounds) | Phase 2 |

## Phase 2 (next touches)

1. Streaming: `ZSTD_createCCtx`/`ZSTD_compressStream2`/`ZSTD_createDCtx`/
   `ZSTD_decompressStream` with owned context handles and reusable buffers;
   in-memory streaming first, file streaming when the fsync/stdlib gaps close.
2. Dictionaries: `ZSTD_createCDict`/`ZSTD_compress_usingDict` plus
   `ZDICT_trainFromBuffer` (already in the amalgamation).
3. Parameters: `ZSTD_CCtx_setParameter` (checksum flag, window log, long
   mode), `ZSTD_getCParams` for level bounds.
4. Multi-frame: loop `ZSTD_decompressStream` to end; skippable-frame skip.
5. Consumer check-in: XVECTOR/ORBITDB/PULSE store formats may want a
   `zstd`-compressed segment option; keep the one-shot API stable for them.
6. Re-pin cadence: track upstream releases; regenerate with the documented
   combine command (SPEC §2).
