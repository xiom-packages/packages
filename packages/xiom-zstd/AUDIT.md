# AUDIT: xiom.zstd

## Status (2026-10-08)

Real vendored implementation at 0.2.0. The pre-pilot module was a
null-pointer stub (`src/zstd.xi`, "links against system-installed libzstd",
all calls passing `0` as placeholder "blocked on compiler *UInt8 dereference
support"); it is preserved in git history only as reference.

| Item | State |
|------|-------|
| Compiler | xiom v0.64.1 |
| Upstream | zstd v1.5.7, single-file amalgamation generated by the official `combine.py` |
| Link model | `--c-source src/zstd_all.c` (shim around `vendor/zstd.c`) |
| FFI confinement | all `extern "C"` in `zstd.xi` (single module, G5) |
| Suite | `tests/test_conformance.xi` |
| Runs | **PASS 8/8 x2** via `scripts/port.ps1` (8192 -> 34 bytes; identical round-trips; invalid frame rejected) |

## G2 pin

- `vendor/zstd.c` SHA256 `208E110A...20BA8E` (2,174,920 B, LF-normalized;
  the Windows `combine.py` output was CRLF and is normalized to LF with the
  pin taken over the stored bytes), `vendor/zstd.h` SHA256
  `9B4BC824...93D88B`, `vendor/LICENSE` (BSD-3-Clause) SHA256
  `70552664...1C9D8`.
- Release archive `zstd-1.5.7.tar.gz` SHA256 `eb33e51f...6fa3`, verified
  against the published `.sha256` asset.
- Full table + generation command + re-pin procedure: `SPEC.md` §2.

## Design notes

- `STATIC_BMI2 0` shim: the link line has no `-mbmi2`, and zstd's `bits.h`
  would otherwise inline `_bzhi_u64` and fail to compile. The define is in
  OUR shim; the vendored file is byte-identical to the generated output.
- `as_mut_ptr` on `&mut Vec[UInt8]` inputs is the proven marshaling idiom on
  this pin (the pre-pilot "blocked on dereference support" note is stale --
  see the sqlite/glfw/sdl3 packages).
- Error paths carry real `ZSTD_getErrorName` text; invalid frames are
  rejected with `zstd: not a valid zstd frame` (content-size sentinel).

## Known limitations

- One-shot API only; no `ZSTD_CCtx`/`ZSTD_DCtx` streaming, no dictionaries
  (`zdict` is in the amalgamation but not exposed), no checksum/parameter
  control, no multi-frame/concatenated handling (Phase 2).
- Compress/decompress copy through XIOM buffers (bound-sized temp + result
  copy); a buffer-reusing API is Phase 2.
- Amalgamation compile takes tens of seconds (240 s watchdog headroom in the
  runner hook).
