## Design notes

- `STATIC_BMI2 0` shim: the link line has no `-mbmi2`, and zstd's `bits.h`
  would otherwise inline `_bzhi_u64` and fail to compile. The define is in
  OUR shim; the vendored file is byte-identical to the generated output.
- `as_mut_ptr` on `&mut Vec[UInt8]` inputs is the proven marshaling idiom on
  this pin (the pre-pilot "blocked on dereference support" note is stale --
  see the sqlite/glfw/sdl3 packages).
- Error paths carry real `ZSTD_getErrorName` text; invalid frames are
  rejected with `zstd: not a valid zstd frame` (content-size sentinel).
- Container surface (0.3.0) is pure XIOM over owned `Vec[UInt8]` buffers:
  byte-indexed reads only, no foreign pointers, no pointer arithmetic
  (B-17/B-20/B-24 discipline), one owned buffer per `zstd_decompress` call,
  flat `Result` shapes (no nested `Result[Option[T]]`; B-26). Frames are
  validated at writer-append time (content size must be recorded) and at
  `frame_at` time via decompress + recorded-size comparison; the index is
  validated exactly at open (exact size, contiguity, nonzero sizes).
- Container format decisions: frames stored exactly as supplied (no
  re-compression); index stores offset + compressed size + decompressed
  size; empty container = 16 bytes; u32 fields cap the format at 4 GiB per
  field with a typed "container too large" error.

## Known limitations

- One-shot codec plus container framing only; no `ZSTD_CCtx`/`ZSTD_DCtx`
  streaming, no dictionaries (`zdict` is in the amalgamation but not
  exposed), no checksum/parameter control (Phase 2).
- The container writer rejects frames whose content size is not recorded in
  the frame header (streaming-style frames) -- typed error, documented;
  supporting them needs a per-frame size override (ROADMAP phase 2 item 4).
- Compress/decompress copy through XIOM buffers (bound-sized temp + result
  copy); a buffer-reusing API is Phase 2.
- Amalgamation compile takes tens of seconds (240 s watchdog headroom in the
  runner hook).
