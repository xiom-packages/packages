# xiom.pbm

> **Status:** `incubating` -- conformance-tested on compiler v0.61.3 (20/20); NOT published yet.
> **Scope:** Netpbm PBM: P1 (ASCII) and P4 (binary) header/raster parsing, 1-bit raster access, and canonical builders with optional header comments.
> **Deps:** `xiom.std` only. No FFI in v0.1.

## Overview

`xiom.pbm` reads and writes the two 1-bit Netpbm bitmap variants on flat
`Vec[UInt8]` buffers:

- **P1**: ASCII header plus a raster of `0` (white) / `1` (black) digits,
  separated by arbitrary Netpbm whitespace.
- **P4**: binary header plus a raster with one bit per pixel, rows padded to
  whole bytes, most significant bit first.

The header parser understands `#` comments anywhere a separator is allowed,
accepts every Netpbm whitespace byte, validates the complete raster up front,
and reports deterministic `pbm: ...` errors. Accessors expose the format,
width, height, the P4 row stride, and a `(x, y)` bit lookup; the builders emit
canonical output with exact P4 padding and optional single-line comments.

## Install / use

```
xiom pkg install xiom.pbm@0.1.0     # consumer, once published
xiom pkg publish                    # maintainer (needs XIOM_REGISTRY_TOKEN)
```

## Quick start

```xiom
use xiom.pbm;

// bits are row-major, top-left origin, 0 = white, 1 = black
let bits = Vec[UInt8].new();
// ... fill bits with width * height 0/1 values ...

match pbm_build_p4(bits, 40, 20, "generated by xiom.pbm") {
  Ok(bytes) => {
    // bytes is a complete, self-contained P4 image
    match pbm_parse_header(bytes) {
      Ok(img) => {
        // pbm_format(&img) == 4, pbm_width(&img) == 40, pbm_height(&img) == 20
        let v = pbm_bit(bytes, 7, 3); // 0, 1, or -1 when out of range
      },
      Err(e) => { /* pbm: ... */ },
    }
  },
  Err(e) => { /* pbm: invalid comment, pbm: non-binary bit, ... */ },
}

// Parse anything a producer writes, including comments and mixed whitespace:
let raw = pbm_parse_header(file_bytes); // file IO is the caller's job
```

## API summary

| Function | Description |
|----------|-------------|
| `pbm_parse_header(data)` | Validates a P1/P4 header and the full raster; returns `PbmImage{format, width, height, data_offset}` |
| `pbm_bit(data, x, y)` | Raster bit at a **top-left origin** coordinate: `0`/`1`, or the documented sentinel `-1` when the coordinate is outside the image or `data` does not parse |
| `pbm_width(img)` | Parsed width (`1..1000000`) |
| `pbm_height(img)` | Parsed height (`1..1000000`) |
| `pbm_format(img)` | `1` for ASCII (P1), `4` for binary (P4) |
| `pbm_row_bytes(width)` | P4 row stride: `(width + 7) / 8`; `0` for `width <= 0` |
| `pbm_build_p1(bits, width, height, bits_per_line, comment)` | Canonical P1: digits separated by single spaces, wrapped to `bits_per_line` (values `< 1` clamp to `1`), exactly one trailing LF |
| `pbm_build_p4(bits, width, height, comment)` | Canonical P4: MSB-first rows padded to whole bytes with zero low bits, no trailing byte |

`bits` is a row-major `width * height` buffer of `0`/`1` bytes for both
builders. `data_offset` is the first raster byte for P4 and the first raster
digit for P1.

## Error model

Every fallible function returns `Result[..., Str]` with a deterministic,
`pbm: `-prefixed message:

| Message | Trigger |
|---|---|
| `pbm: truncated header` | buffer ends inside the magic |
| `pbm: bad magic` | bytes 0-1 are not `P1`/`P4` |
| `pbm: missing whitespace after magic` | byte 2 is not whitespace |
| `pbm: missing width` / `pbm: missing height` | dimension token absent or non-decimal |
| `pbm: invalid width` / `pbm: invalid height` | dimension `<= 0`, `> 1000000`, or 10+ digits |
| `pbm: missing whitespace after height` | P4 height not followed by a whitespace byte |
| `pbm: truncated raster` | P4 or P1 raster shorter than `width * height` pixels |
| `pbm: non-binary digit` | P1 raster byte that is neither `0`/`1` nor whitespace |
| `pbm: extra tokens` | P1 raster longer than `width * height` digits, or non-whitespace bytes after a P4 raster |
| `pbm: bit buffer size mismatch` | builder `bits` length != `width * height` |
| `pbm: non-binary bit` | builder bit value other than `0`/`1` |
| `pbm: invalid comment` | builder comment contains a byte `< 32` or `== 127` |

`pbm_bit` is the one non-`Result` accessor: it returns `-1` instead of an
error, and `pbm_parse_header` is the way to tell "out of range" from
"malformed input".

## Format notes

- Whitespace is SPACE, TAB, LF, CR, VT, FF. A `#` comment runs to the end of
  the line and acts as a separator anywhere in the header, including between
  the height token and a P1 raster.
- After the magic at least one whitespace byte is required. For P4, exactly
  one whitespace byte terminates the height token; the raster is raw bytes from
  there on. A P1 raster contains only `0`/`1` digits and whitespace -- `#` is
  data once the raster has started.
- P4 rows are independent: bit `x` is bit `7 - (x % 8)` of byte
  `data_offset + y * pbm_row_bytes(width) + x / 8`. The low bits of each row's
  final byte are padding; builders write zeros and readers ignore them.
- Builders accept an empty comment (no line emitted) or a printable comment,
  emitted as `# <comment>` on its own line right after the magic.
- `1` is black and `0` is white, matching the Netpbm convention.

## Testing

From the repo root:

```
.\scripts\port.ps1 -Package xiom.pbm
```

20 conformance tests cover built and hand-built P1/P4 parsing, comments and
all six whitespace bytes, exact offsets, the error catalog above, P4 padding
for 1/2/3/8/9-bit rows, arbitrary P1 whitespace, 5x3 per-row padding, a
P1->P4->P1 semantic and byte-exact round trip, canonical builder literals,
wrapping/clamping, builder validation, comment emission, the `pbm_bit`
sentinel, `pbm_row_bytes` boundaries, and the 1,000,000 dimension cap.

## Limitations

- One bit per pixel, P1/P4 only: no PGM/PPM/PAM (see `xiom.ppm` for P3/P6), no
  palettes, no multi-image streams.
- 1,000,000 maximum per dimension; the whole raster is in memory (no
  streaming).
- No file IO, scaling, rotation, inversion, or automatic P1<->P4 conversion:
  move bits through `pbm_bit` and the builders.
- `pbm_bit` re-parses the header on each call; for bulk access parse once and
  use `pbm_row_bytes` with P4 arithmetic.
