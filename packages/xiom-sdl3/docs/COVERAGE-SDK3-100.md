Recorded 2026-10-11 by the `sdk100-sdl3-100` agent worktree. Byte source:
SDL3 headers + DLL shipped with `C:\VulkanSDK\1.4.350.0` (3.4.8). Compiler:
pinned **v0.64.3** (`scripts/port.ps1`). Provenance: `PROVENANCE.md`.

## 2. Module split (generated by `tools/gen_sdl3_full.py`)

- 67 generated modules in `src/` (`sdl3_full_<family>[_N].xi`), 59 of them
  carry functions (>64-function families split: `stdinc` x3, `video` x2,
  `render` x2, `gpu` x2, `gamepad` x2, `surface` x2 and the other
  51 families single), plus `sdl3_full_names.xi` (oracle lists) and
  `sdl3_full_registry.xi` (load+close wiring for every function module).
- One wrapper per bound function with scalar-correct ABI mapping:
  pointers/handles -> `Int`, `const char *` -> `Str`, `bool` -> `Bool`
  (`UInt8` ABI), `float` -> `Float64` param (cast `Float32`), narrow integer
  returns masked/sign-extended with exact declared widths (B-19), `char *`
  returns -> `Str` (copy).
- Name-collision handling is deterministic and documented: `SDL_Log`
  (logging, `sdl3full_log`) vs `SDL_log` (stdinc math, `sdl3full_math_log`);
  infrastructure names are `sdl3full_module_load_*` / `..._close_*` so no
  SDL function wrapper can clash with them.

## 5. Caveats / documented study items (bindings-lane discipline B-11..B-20)

- **B-12 (open)**: floating-point cast-call returns are miscompiled on
  v0.64.3 -- the 56 fp-return wrappers are generated but their values are not
  trustworthy and are not exercised; re-verify when the compiler fixes B-12.
- **Variadic functions (16)**: bound on the fixed parameter list only (e.g.
  `sdl3full_log(lib, fmt)`); no vararg marshalling from XIOM.
- **Ownership of `char *` returns**: wrappers copy via `Str::from_c_str` and
  do not free caller-owned returns (`SDL_GetPrefPath`,
  `SDL_GetCurrentDirectory`, `SDL_GetClipboardText`, ...). The hand-written
  `sdl3.xi` wrappers remain authoritative for ownership-sensitive calls.
- **Struct-by-value ABI**: `SDL_GUID`/`SDL_FColor` params are 16-byte
  Win64 by-reference -> `Int` address of a caller-owned slot; the 5
  `SDL_GUID`-returning functions use the sret shape (`out` address + Bool).
- **Callback params** are raw `Int` addresses (B-13/B-18); use the proven
  fixed-dispatcher pattern from `sdl3.xi`.
- **Compiler finding surfaced while building this suite (v0.64.3, candidate
  B-21)**: with a large module catalog, an unqualified cross-module `const`
  import resolves only for the LAST `use`d module; module-qualified access
  (`alias.CONST`) is stable. Repro shape: in `packages/xiom-sdl3`, a test that
  `use`s `xiom.sdl3.full.init;` then `xiom.sdl3.full.names;` and references
  `SDL_INIT_VIDEO` unqualified fails ("undefined variable"), while
  `init.SDL_INIT_VIDEO` resolves; reversing the import order flips which const
  is undefined. Workaround used by `tests/test_full_surface.xi`:
  module-qualified constant references.
- **Live confirmation of B-12** during probe development: `SDL_randf()`
  through the loader returned garbage (580218) on v0.64.3 while the C-side
  value is in [0,1) -- consistent with the recorded finding.
