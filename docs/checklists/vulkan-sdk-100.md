## 1. Definition of Done (per component; measurable, airtight)

100% means ALL of these, evidenced:
1. **Oracle inventory**: committed script parses the component's public header(s)
   and emits the function/enum inventory (count N). No manual lists.
2. **Declared**: every oracle function has a typed XIOM binding (generated;
   committed generator). No hand-maintained function lists for >50-fn APIs.
3. **Loadable**: suite resolves EVERY function name at runtime against the real
   DLL (or vendored build) and prints `resolved=N/N`; N must equal the oracle N.
   SKIP (green) when the DLL is absent -- never a link-time dependency.
4. **Constants**: every enum/macro value bound as `pub const` (count check in
   the coverage report).
5. **Vulkan only -- struct metadata**: size + member offsets for every struct
   (generated by compiling an offset dumper against the SDK headers; exact).
6. **Functional probes**: real calls (not just resolution) covering each major
   family; suite green **x2** via `scripts/port.ps1`.
7. **Package hygiene**: `package.xi`, README, ROADMAP, SPEC, AUDIT, STATUS.json,
   `scripts/status.ps1` record (run_by/commit/checked), atomic conventional
   commits, clean worktree. Relay/publish is done by the coordinator.
8. **Coverage report**: `docs/COVERAGE.md` in each package: oracle N vs bound N
   vs runtime-resolved N + dates/versions.

## 2. Binding architecture (proven lane patterns)

- **Dynamic loader** (sdl3 template): symbol-handle struct `p_*: Int` +
  `dl.dl_sym` resolver + thin typed wrappers casting `fn(...)`. No SDK headers
  at build time; runtime DLL from `Bin` (PATH prepend in tests). Absent = SKIP.
- **Vulkan specifics**: `vulkan-1.dll` exports only the loader entry points;
  everything else resolves via `vkGetInstanceProcAddr(NULL/instance, name)` and
  `vkGetDeviceProcAddr(device, name)`. Generated resolver module + per-family
  wrapper modules; alias commands included.
- **Vendored route** (meshopt/assimp template) where no shared DLL exists
  (SPIRV-Reflect): vendor source byte-pinned (`vendor/** -text`, per-file
  SHA256 in SPEC), bridge with scalar/owned-slot ABI.
- **C++ APIs** (glslang TShader, VMA): committed C++ bridge with scalar ABI +
  owned-slot copies out (B-20: never read through foreign pointers).
- **COM/vtable APIs** (DXC): generated C++ bridge over the IDxc* interfaces
  (vtable calls inside C; scalar ABI + owned-slot copies out).
- **Discipline (non-negotiable)**: B-11..B-20 -- byte-indexed slot writes, one
  owned slot per out-param, no raw pointer arithmetic (Int address math only),
  C copies into XIOM-owned slots, canonical `Vec[UInt8]`, structured ifs,
  `f_`/`my_` local names in confined blocks, SKIP classification, x2 evidence,
  explicit-path cleanup (no stray `a.exe`).

## 6. Risks / notes

- Scale: Vulkan struct metadata is ~1700 sizes + ~15k offsets -- generated,
  never hand-written. Family-split modules keep files <600 lines.
- `slang.h` C API is large; generator mandatory; bind every exported C entry
  point present in slang.dll.
- DXC is COM; bridge overhead accepted (scalar ABI, owned-slot copies).
- glslang's public C surface is small; the compile path is C++ -- bridge it and
  document the split in COVERAGE.md.
- Never link SDK libs at build time; runtime DLL only, SKIP when absent.
